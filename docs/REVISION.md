# Informe de revisión · 3.3.0

## Hallazgos y cambios
- Crítico: server/auth.js contenía una copia de las rutas y no exportaba las funciones esperadas. Se reconstruyó autenticación JWT/bcrypt, con validación del usuario y empresa en cada solicitud, clave inicial obligatoria y revocación de sesiones anteriores al cambiar clave o desactivar cuenta.
- Crítico: coexistían llamadas db.prepare y db.execute; se unificaron rutas operativas, auditoría, empresas, exportación y carga demo con libSQL. Se espera a inicializar el esquema antes de escuchar. SQLite local es alternativa a Turso.
- Alto: CORS permisivo, CSP desactivada, contraseña predeterminada y recuperación inexistente. Se restringió origen, habilitó CSP, añadió límite de login, eliminó clave por defecto y sustituyó preguntas por restablecimiento administrado. Se impide exportar a lectores/editores. No se permite creación de empresas por administradores de una empresa.
- Alto: edición inexistente, borrado irreversible y permisos inconsistentes. Se implementó PUT, papelera y restauración de operaciones; desactivación de usuarios en vez de borrado y protección de proveedores relacionados. Los registros históricos conservan sus referencias de usuario.
- Medio: caja chica creaba valores fijos y no permitía registrar gastos desde el navegador. Se añadió formulario, selección, detalle y saldo. Se permite saldo negativo visible para registrar gastos reales; no se ha establecido un flujo de aprobación ni cierre contable.
- Medio: interfaz básica, filtros desconectados, totales sin actualización y PWA incompleta. Se añadió navegación lateral adaptable, filtros, estados, fecha Lima, botones condicionados por permisos, iconos y manifiesto funcional.
- Medio: archivos de migración y pruebas estaban intercambiados; Dockerfile y nginx.conf tenían nombres erróneos; documentación truncada. Se reordenaron y se simplificó Docker para proxy externo.

## Limitaciones / decisiones
La revisión no equivale a una auditoría certificada ni a una prueba de penetración. No se instaló npm por fallo DNS (EAI_AGAIN), por lo que no se ejecutaron Vitest, Playwright, Express, Turso ni Docker. No se generó package-lock.json. Las cuatro pruebas estáticas, sintaxis bash y prueba del esquema SQLite con papelera sí pasaron. No hubo base de datos de producción adjunta.

Las operaciones usan REAL heredado; el frontend suma centavos redondeados. Se recomienda migración contable futura a enteros en centavos, con conciliación de datos existentes. La referencia hash no es firma digital certificada ni prueba de integridad. La auditoría es de aplicación: no es inmutable ni está en una transacción con cada modificación; el fallo de registro se escribe en logs. Se recomienda auditoría transaccional, control de concurrencia completo, paginación de operaciones y retención de datos antes de un uso intensivo. El logout elimina la cookie del navegador; no implementa lista de revocación individual para tokens copiados. Los nombres de banco derivados de cuentas son una heurística heredada, no una verificación bancaria. No se ha verificado el diseño visual en un navegador. La caja chica permite eliminar gastos solo a admin; no incluye recuperación de gastos. No se han incluido datos de ejemplo del original en el seed ampliado, para evitar cargar nombres, cuentas y contraseñas de muestra en producción.
